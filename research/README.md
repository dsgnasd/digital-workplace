## Главное в пяти пунктах

1. **Сквозной цикл проекта работает:** создание → утверждение → выдача доступов → старт → изменения → пересмотр → закрытие с отзывом доступов.
2. **Первый прогон:** 8 из 14 задач успешно, 3 провала из-за отсутствия функций.
3. **После шести раундов правок:** 24 из 24 задач в текущем наборе. Задачи службы поддержки убраны вместе с ролью: заявки выполняются в сервис-деске компании (раздел 14 отчёта).
4. **Покрытие историй прототипом:** 49 из 49 (было 22 реализовано, 3 частично, 13 нет). Эпик I — модели работы с заказчиком.
5. **Что требует рабочей версии:** доставка уведомлений в VK Teams или на почту, реальные данные ИИ-шлюза, синхронизация с кадровой системой, роль «Аудитор» для ИБ. И проверка на живых пользователях (раздел 7 отчёта).

## Как повторить тест после правок прототипа

```bash
cd research/tools
```

```bash
node persona-tests.js
```

Скрипт берёт актуальный код из `index.html`, на свежих демо-данных проходит 24 задачи и перезаписывает `persona-results.json`.

## Ограничения

Персоны и пользователи синтетические. Метод хорошо находит отсутствующие функции и логические разрывы, но не заменяет тестирование с людьми. План проверки на реальных пользователях — в разделе 7 файла [04-synthetic-testing.md](04-synthetic-testing.md).
